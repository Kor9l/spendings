# Установка на свой сервер

Подойдёт любой компьютер с Docker, который работает постоянно: мини-ПК, NAS, VPS за 3–5 $ в месяц. Приложению хватает 512 МБ памяти.

## 1. Запуск

```bash
git clone https://github.com/Kor9l/spendings.git && cd spendings
cp .env.example .env
```

В `.env` задайте как минимум:

| Переменная | Что это |
|---|---|
| `POSTGRES_PASSWORD` | пароль базы, любой длинный |
| `SPENDINGS_REMEMBER_ME_KEY` | ключ «Запомнить меня»: `openssl rand -hex 32` |
| `SPENDINGS_DOMAIN`, `SPENDINGS_RP_ID`, `SPENDINGS_ORIGIN` | адрес, по которому открывают приложение (см. ниже) |

```bash
docker compose --profile app up -d --build
```

Поднимутся три контейнера: `db` (PostgreSQL 18), `app` (приложение, порт 8080 только на этом компьютере) и `backup` (ночной бэкап). Откройте адрес приложения — мастер первого запуска попросит создать учётную запись.

Обновление: `git pull && docker compose --profile app up -d --build`. Миграции базы применяются сами при старте.

## 2. Доступ с телефона по HTTPS

Passkeys и установка PWA работают только по HTTPS. Есть два способа.

### Tailscale — проще и без открытых портов

Приложение доступно только вашим устройствам в tailnet.

1. Поставьте [Tailscale](https://tailscale.com/download) на сервер и телефон, войдите в один аккаунт.
2. На сервере: `tailscale serve --bg 8080`. Tailscale выпустит сертификат и покажет адрес вида `https://server.tail1234.ts.net`.
3. В `.env`:
   ```
   SPENDINGS_RP_ID=server.tail1234.ts.net
   SPENDINGS_ORIGIN=https://server.tail1234.ts.net
   ```
   и `docker compose --profile app up -d`.

### Caddy — свой домен, доступ из интернета

1. Направьте домен (A-запись) на сервер, откройте порты 80 и 443.
2. В `.env`:
   ```
   SPENDINGS_DOMAIN=money.example.com
   SPENDINGS_RP_ID=money.example.com
   SPENDINGS_ORIGIN=https://money.example.com
   ```
3. `docker compose --profile app --profile https up -d --build`

Caddy сам получит сертификат Let's Encrypt и будет его продлевать. Приложение по-прежнему слушает только localhost: снаружи доступен лишь Caddy.

## 3. Телефон

- **Установка:** откройте адрес в Chrome (Android) или Safari (iPhone) → «Установить приложение» / «На экран „Домой“». Долгое нажатие на иконку → «Быстрый расход».
- **Вход по отпечатку или Face ID:** войдите паролем → Настройки → Ключи входа → «Добавить ключ». Добавьте ключ на каждом устройстве. Пароль продолжает работать.
- Без сети приложение показывает страницу «Нет связи»: данные хранятся только на сервере.

## 4. Бэкапы

Контейнер `backup` делает `pg_dump` при старте и каждую ночь в `BACKUP_AT` (по умолчанию 03:30) в каталог `./backups` (или `BACKUP_DIR`), хранит `BACKUP_KEEP_DAYS` дней (по умолчанию 30).

**Каждый бэкап проверяется:** дамп восстанавливается во временную базу, число операций и версия схемы сравниваются с рабочей. Ошибка видна в логе:

```bash
docker compose logs backup
```

**Копия вне сервера.** Бэкап на том же диске не спасёт от его поломки. Варианты:

- `BACKUP_COPY_COMMAND` в `.env` — команда, которая получает путь к дампу в `$BACKUP_FILE`, например `scp` на NAS (ключ положите в каталог бэкапов);
- или синхронизируйте каталог `backups/` с облаком средствами хоста (rclone, Syncthing, restic) — например, cron-задачей в 04:00.

Дополнительно в приложении есть ручная выгрузка всех данных в JSON: Настройки → Бэкап.

## 5. Восстановление

```bash
./deploy/scripts/restore.sh backups/spendings_2026-10-11_0330.dump
```

Скрипт спросит подтверждение, остановит приложение, пересоздаст базу из дампа и запустит приложение снова. Учётная запись и ключи входа восстанавливаются вместе с данными.

**Отрепетировано 11.10.2026:** стенд с 50 000 операций → ночной бэкап (2,6 МБ, проверка прошла) → удаление всех операций → `restore.sh` → 50 000 операций на месте, приложение снова в строю.

## 6. Демо-данные и скорость

```bash
SPENDINGS_DEMO_OPERATIONS=50000 ./gradlew bootRun
```

заполнит **пустую** базу: три счёта и 50 тысяч операций за три года. Владельца по-прежнему создаёт мастер.

`./gradlew perfTest` — проверка скорости на 50 тысячах операций (медиана, сервер, без сети; 11.10.2026): дашборд 185 мс, операции 166 мс, отчёты 114 мс, бюджеты 26 мс, вклады 13 мс. Порог — 300 мс.
